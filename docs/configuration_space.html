Model

VMF combines one or more YAML files into a single configuration. The resulting document chooses the campaign shape, module graph, execution mode, and behavior of each module instance.

YAML composition Split reusable module graphs from SUT-specific anchors, paths, and framework settings.
Top-level sections vmfVariables, vmfFramework, vmfModules, vmfDistributed, vmfClassSet, and module-specific sections.
Module graph Required storage and root controller, with controller children and nested submodules.
Module parameters A module reads from its id section when present, otherwise from its className section.

Relationships

These are the relationships that matter when reading or authoring a VMF configuration.

Anchors feed parameters vmfVariables commonly defines values such as SUT_ARGV and INPUT_DIR. Module sections then reference those values.
Topology selects modules vmfModules determines which classes are instantiated and which modules are children of controllers, generators, outputs, or other modules.
Instance names select settings A repeated class needs an id. Its settings must be under that id, as with CorpusMinExecutor.
Storage sort depends on feedback Storage defaults sort by FITNESS, which feedback modules write. Changing sort keys changes how generators choose saved test cases.
Executors feed feedback and outputs Executor coverage, crash, hang, and timing fields are consumed by feedback, statistics, corpus saving, and minimization.
Distributed mode adds CDMS controls CDMS settings live in a separate mode: vmfDistributed, controller-level CDMS options, and server-facing modules.

Configuration Decision Tree

Use this path when choosing a VMF configuration shape before filling in module defaults.

Choose execution mode
  • Standalone: omit vmfDistributed.
  • Distributed: configure vmfDistributed.serverURL and server modules.
Choose platform executor
  • Linux AFL++: AFLForkserverExecutor.
  • Windows Frida: FridaExecutor.
Choose seed source
  • Files: DirectoryBasedSeedGen.inputDir.
  • Generated: KLEE, strings, dictionary, Gramatron, or trivial seed.
  • Distributed: server seed or corpus initialization.
Choose generation strategy
  • Simple GA: GeneticAlgorithmInputGenerator.
  • Adaptive AFL-style: MOPTInputGenerator.
  • CmpLog-guided: RedPawnInputGenerator.
Choose mutator family
  • AFL mutator set for byte-level fuzzing.
  • Dictionary or stacked mutators for targeted composition.
  • Gramatron mutators for grammar-aware campaigns.
Choose feedback and outputs
  • AFLFeedback or AFLFavoredFeedback.
  • Save corpus, compute stats, minimize corpus, log or export metadata.
  • Distributed outputs only when CDMS is in use.

Distributed Mode

Distributed mode is separated from standalone VMF configuration because it adds CDMS connection settings, corpus import/export modules, and server-facing output behavior.

Connection vmfDistributed configures server URL, proxy, retry behavior, tasking poll rate, and client name.
Controller handoff Controller instances provide CDMS batch size and corpus update cadence through CDMSCommandAndCorpusHandler.
Corpus input ServerSeedInitialization and ServerCorpusInitialization retrieve seed or corpus data from CDMS.
Corpus output ServerCorpusOutput, ServerCorpusMinOutput, and StatsOutput.sendToServer publish data back to CDMS.
